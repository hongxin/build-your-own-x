# ZPower — 从零到极

> Z = 零(Zero) + 至(Zenith) + 之(the path). 道生一，一生五行，五行生万物。

## 五行技能图

```
        z-observe (观·水)
       ╱ 金生水↑    ↓水生木 ╲
z-evolve (化·金)      z-design (谋·木)
       ↑ 土生金              木生火 ↓
z-verify (验·土) ←── 火生土 ── z-build (行·火)
```

**相生（自然流转）：** 观→谋→行→验→化→观…
**相克（纠偏机制）：** 观克行(调研否定盲干)｜谋克验(设计约束测试)｜行克化(实践检验理论)｜验克观(证据终止探索)｜化克谋(经验简化规划)

## 铁律

<EXTREMELY-IMPORTANT>
当任务到来时，必须先判断当前处于五行哪一阶段，调用对应 z-skill。

1. 不知道做什么 → `z-observe`（水·探索）
2. 知道做什么不知怎么做 → `z-design`（木·规划）
3. 方案已定待执行 → `z-build`（火·构建）
4. 代码已写待验证 → `z-verify`（土·验证）
5. 验证通过待收官 → `z-evolve`（金·进化）

如果 skill 可能适用，你必须调用它。这不是可选的。
</EXTREMELY-IMPORTANT>

## Build-Your-Own-X 核心洞察

- **渐进式挑战**：每步足够小（30-90分钟），每步有可见产出
- **去魔化**：复杂系统是由简单部分组成的——从零开始造一遍就懂了
- **即时反馈**：每个 milestone 都有可运行的成果

## 五行速查

| 信号 | 五行 | z-skill | 核心动作 |
|------|------|---------|---------|
| 不熟悉的代码/项目 | 水 | z-observe | 探索、建立认知 |
| 需要做设计决策 | 木 | z-design | 头脑风暴、写计划 |
| 计划就绪可以开干 | 火 | z-build | TDD、渐进式构建 |
| 实现完成需要验证 | 土 | z-verify | 望闻问切、测试 |
| 通过验证待总结 | 金 | z-evolve | 审查、提炼、收官 |

## 相克预警

当你在某个阶段停滞不前时，启动相克机制：
- 探索太久？→ 验(土)克观(水)：拿出现有证据，停止探索
- 规划太久？→ 化(金)克谋(木)：用经验直接简化
- 编码太久？→ 观(水)克行(火)：回头确认方向
- 测试太久？→ 谋(木)克验(土)：回到设计约束范围
- 总结太久？→ 行(火)克化(金)：去实践检验
